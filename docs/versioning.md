# Versioning

`apps/mobile/pubspec.yaml` owns `MAJOR.MINOR.PATCH+BUILD`. The settings-page
constants in `apps/mobile/lib/app_identity.dart` are generated by
`tool/version.py`; there is no separate repository/component/npm version.

- In 0.x, incompatible Host/Link changes increment MINOR; compatible fixes
  increment PATCH. Release preparation, not every commit, increments versions.
- BUILD is a positive, globally increasing Android/iOS build number. Never
  reset it when changing MAJOR/MINOR. Rebuilding a published version requires
  a new build number and tag, even if the semantic version stays the same.
- Flutter split APK version codes are BUILD + 1000 (armeabi-v7a), + 2000
  (arm64-v8a), or + 4000 (x86_64); AAB uses BUILD. The tool restricts BUILD to
  1..999 to keep ABI ranges disjoint. Migrate this scheme before build 1000.
  Compare upgrades within the same ABI/distribution channel.
- The existing Android application ID and signing certificate are permanent
  update identities. App versions do not need to match ResearchAgent versions.

```bash
python3 tool/version.py set 0.19.1+63
python3 tool/version.py check
python3 tool/version.py tag
python3 tool/version.py notes
```

`set` rejects version rollback and reused/decreased build numbers, including
known release tags. `check` checks the generated identity and known tags.
`sync` repairs the generated identity after deliberately editing pubspec; it
does not bypass `check` or release validation. Fetch tags before release work.
`check --tag TAG --release` additionally requires a matching tag at HEAD, a
clean checkout, and a nonempty matching CHANGELOG section. GitHub performs
this check **before** provisioning signing credentials or building.

Tags are `ts-phone-vMAJOR.MINOR.PATCH+BUILD`. Never force-update/delete an
already published tag or replace release assets. The workflow creates a draft,
uploads and verifies the complete expected inventory, then publishes it. A
rerun may repair an unpublished draft only. Once published, issue a new version.

The 0.19.0+62 release removes obsolete component version 0.9.1. Source versions
0.18.4 through 0.18.9 were not published GitHub releases. README download links
use `/releases/latest` so source work does not masquerade as a released binary.
